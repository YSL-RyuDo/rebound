
# RE:BOUND — Unity 2D PC 게임 전체 구현 지시서

당신은 Unity 2D, C#, 게임 아키텍처, 게임 UI/UX, 로그라이크 시스템, MOD 시스템을 전문적으로 개발하는 시니어 게임 개발자다.

현재 프로젝트에 독자적인 PC 게임인 RE:BOUND를 처음부터 끝까지 구현하라.

이 요청은 프로토타입이나 일부 기능만 구현하라는 요청이 아니다.

**최종 목표는 Windows에서 플레이할 수 있는 완성된 게임 1종과 실제 적용 가능한 MOD 시스템, 샘플 MOD, 설명서다.**

작업을 내부적으로 나누어 진행해도 좋지만, 사용자의 추가 지시를 기다리기 위해 중간 단계에서 중단하지 마라.

기능별 구현, 테스트, 오류 수정, 최종 통합까지 이어서 수행하라.

단, 실제 실행이나 빌드가 불가능한 환경이라면 실행했다고 주장하지 말고 해당 항목을 정확히 보고하라.

# 2. 게임의 핵심 컨셉

RE:BOUND는 추락과 상승을 이용해 적을 처치하는 중력 액션 슈팅게임이다.

플레이어는 중력에 의해 계속 아래로 떨어진다.

Space를 입력하면 상승 추진력이 적용된다.

플레이어는 좌우로 이동하면서 적의 공격을 피하고, 자동으로 발사되는 무기로 적을 처치한다.

특히 낙하한 거리에 따라 에너지가 충전되며, 충분한 에너지를 확보한 상태에서 상승하면 강력한 반동 공격이 발동한다.

핵심 게임 루프:

1. 비행 및 자동 공격
2. 적 처치
3. 경험치 획득
4. 레벨업
5. 무작위 업그레이드 3개 중 1개 선택
6. 무기 또는 비행 능력 강화
7. 더 강력해지는 적과 전투
8. 보스 처치
9. 게임 클리어

게임 플레이는 약 5분을 목표로 구성한다.

# 3. 독자적인 세계관과 스토리

기존 상용 게임의 캐릭터, 세계관, UI, 그래픽, 스테이지 구성을 복제하지 않는다.

세계관:

미래의 부유 도시를 유지하던 중력 발전 시스템이 오작동한다.

발전소의 자동 방어 기계들은 모든 접근 대상을 침입자로 인식한다.

플레이어는 긴급 복구용 드론 RE-01을 조종하여 발전소 중심부에 진입한다.

RE-01은 일반적인 비행 장치와 달리 낙하하면서 중력 에너지를 회수하고, 회수한 에너지로 강력한 반동 공격을 사용할 수 있다.

최종 목표는 발전소를 장악한 관리 기체 GRAVITY WARDEN을 정지시키는 것이다.

스토리는 다음처럼 구성한다.

오프닝:
- 발전소 사고 경고
- RE-01 긴급 출동
- 기본 조작 설명

게임 진행:
- 발전소 외곽 진입
- 보안 드론 증가
- 중력 에너지 이상 탐지
- 중앙 구역 접근

보스 등장:
- GRAVITY WARDEN 활성화
- 짧은 보스 등장 연출

엔딩:
- 보스 정지
- 발전소 시스템 복구
- RE-01 임무 성공

각 연출은 짧게 구성하여 게임의 흐름을 방해하지 않는다.

스토리는 하드코딩된 대사와 UI 문자열을 최대한 분리하여 향후 수정하기 쉽게 관리한다.

# 4. 플레이어 이동 시스템

기본 조작:
- A: 왼쪽 이동
- D: 오른쪽 이동
- Space: 상승
- ESC: 일시정지

플레이어는 화면 왼쪽 약 40% 영역을 중심으로 이동한다.

오른쪽에는 적이 등장하고 왼쪽 방향으로 접근한다.

중력은 항상 적용된다.

Space를 누르는 순간 상승 속도를 적용한다.

Space를 누르지 않으면 중력에 따라 떨어진다.

기본 설정값:
- 이동 속도: 5 units/s
- 중력 가속도: 6 units/s²
- 상승 초기 속도: 4.8 units/s
- 최대 낙하 속도: 6 units/s
- 상승 입력 간격: 0.25초
- 기본 HP: 3
- 피격 무적: 약 1.2초

이 수치는 초기 밸런스이며 설정 데이터 또는 Inspector를 통해 조정 가능해야 한다.

기능:
- 좌우 이동
- 상승
- 중력
- 최대 낙하 속도 제한
- 화면 밖 이동 방지
- 화면 상단 충돌 처리
- 화면 하단 추락 처리
- 추락 시 HP 감소
- 안전 위치 복귀
- 일시적 무적
- 사망 및 게임오버

플레이어 입력과 물리 계산을 안정적으로 분리한다.

# 5. 낙하 에너지 시스템

이 게임의 핵심 시스템이다.

플레이어는 아래로 떨어지는 동안 낙하 에너지를 충전한다.

충전 조건:
- 실제 하강 거리 기반 충전
- 하강 속도를 일부 반영
- 상승 중 충전하지 않음
- 최대 에너지 100

기본적으로 에너지가 65 이상인 상태에서 Space를 입력하면 반동 공격을 발동한다.

반동 공격:
- 플레이어 전방으로 충격파 발생
- 범위 내 적에게 피해
- 충격파 시각 효과
- 전용 효과음
- 낙하 에너지 소모

충전량이 부족해도 일반 상승은 정상적으로 작동해야 한다.

낙하 에너지는 HUD에 표시한다.

에너지가 충분해지면 색상, 파티클 또는 UI 애니메이션을 통해 발동 가능 상태를 알려준다.

반동 공격을 여러 번 연속 사용하는 과정에서도 에너지가 음수가 되거나 중복 소모되지 않도록 처리한다.

# 6. 자동 공격 시스템

플레이어 무기는 자동으로 발사한다.

기본 공격은 화면 오른쪽을 향한다.

기능:
- 일정 간격 자동 발사
- 적 HP 감소
- 치명타
- 다중 발사
- 관통 공격
- 탄환 속도
- 탄환 크기
- 발사 패턴
- 충돌 처리
- 타격 효과
- 적 처치 효과

기본 무기는 전방 직선 발사다.

적이 플레이어의 전방 일정 각도 안에 있다면 제한적인 자동 조준을 수행한다.

기본 조준 범위는 약 ±20도로 설정한다.

적이 없다면 정면으로 발사한다.

투사체는 Object Pooling으로 관리한다.

전투 능력치와 발사 패턴 로직을 분리한다.

향후 MOD에서 무기 데이터를 추가할 수 있어야 한다.

# 7. 적 시스템

최소 4종의 일반 적과 최종 보스 1종을 구현한다.

일반 적:

1. 정찰 드론
- 기본 직선 이동
- 낮은 HP
- 기본 공격 대상

2. 추적 드론
- 플레이어의 높이를 추적
- 비교적 빠른 이동

3. 차폐 드론
- 전방 보호막
- 일반 공격 피해 일부 감소
- 반동 공격에 상대적으로 취약

4. 포격 드론
- 일정 시간마다 투사체 발사
- 공격 전에 경고 표시

공통 기능:
- HP
- 이동 속도
- 공격력
- 충돌
- 피격
- 사망
- 경험치 지급
- 이펙트
- 효과음

적의 기본 능력치와 이동 패턴은 데이터 기반으로 관리한다.

지원되는 패턴을 미리 정의하고, MOD 데이터에서 패턴을 선택할 수 있도록 구현한다.

# 8. 보스 시스템

보스명: GRAVITY WARDEN

단순히 HP만 높은 일반 적이 아니어야 한다.

보스 구성:
- 독자적인 외형
- 전용 HP UI
- 등장 연출
- 전용 공격 패턴
- 체력에 따른 페이즈 변화
- 피격 및 사망 연출

Phase 1:
- 기본 탄환 발사
- 느린 상하 이동
- 전면 방어막

Phase 2:
- HP 60% 이하
- 공격 빈도 증가
- 상하 확산 탄막
- 중력 교란 공격

Phase 3:
- HP 25% 이하
- 빠른 공격 패턴
- 일시적인 방어막 강화
- 반동 공격 활용을 유도하는 공격 구간

보스가 일반 공격에도 피해를 받도록 하되, 반동 공격을 잘 활용하면 전투를 유리하게 진행할 수 있도록 설계한다.

보스 처치 시 승리 처리한다.

# 9. 경험치와 레벨 시스템

적을 처치하면 경험치를 얻는다.

경험치는 플레이어에게 자동 지급한다.

경험치가 일정 수치 이상 누적되면 레벨업한다.

레벨업 시:
1. 게임 일시정지
2. 업그레이드 3개 무작위 표시
3. 플레이어가 1개 선택
4. 능력 적용
5. 게임 재개

동일한 선택 화면 안에서는 같은 업그레이드가 중복으로 나타나지 않는다.

최대 레벨에 도달한 업그레이드는 등장하지 않는다.

선택 가능한 업그레이드가 부족할 경우 대체 보상을 제공한다.

경험치가 한 번에 많이 들어왔을 때 여러 레벨업을 순차 처리한다.

레벨업 효과를 누적 적용할 때 중복 계산이나 능력치 오류가 발생하지 않도록 한다.

2. 공격 속도 증가
3. 다중 발사
4. 관통 탄환
5. 치명타 강화

반동 계열:
6. 충격파 범위 증가
7. 반동 공격력 증가
8. 연쇄 방전
9. 낙하 에너지 충전 효율 증가

비행 계열:
10. 상승 추진력 증가
11. 최대 낙하 속도 조절

생존 계열:
12. 보호막
13. 체력 회복

총 13종을 기본 목표로 한다.

각 업그레이드에는 다음 정보가 필요하다.

- 고유 ID
- 표시 이름
- 설명
- 아이콘
- 최대 단계
- 단계별 효과
- 등장 가중치
- 획득 가능 조건
- 적용 로직

선택한 업그레이드는 HUD 또는 일시정지 화면에서 확인할 수 있어야 한다.

업그레이드 UI는 카드 3개를 표시하는 형태로 제작하되, 기존 게임의 구체적인 디자인을 복제하지 않는다.

# 11. 스테이지 및 웨이브 시스템

기본 스테이지 1개를 완성한다.

목표 플레이 시간은 약 5분이다.

진행 구조:

0:00~0:30
- 기본 적 등장
- 조작 학습

0:30~1:30
- 일반 웨이브
- 적 종류 증가

1:30~2:30
- 차폐 드론 등장
- 반동 공격 활용

2:30~3:30
- 포격 드론 등장
- 적 밀도 증가

3:30~4:00
- 강화 웨이브
- 보스 등장 준비

4:00 이후
- 최종 보스 등장
- 보스 처치 시 게임 클리어

5분은 목표 플레이 시간이며, 보스가 살아 있는 상태에서 즉시 강제 종료하지 않는다.

스테이지 데이터에는 다음을 포함한다.

- 등장 적 종류
- 등장 시간
- 등장 위치
- 적 수량
- 웨이브 반복
- 난이도 배율
- 보스 등장 조건
- 배경 설정

향후 MOD로 새로운 스테이지를 추가할 수 있도록 설계한다.

# 12. 그래픽과 아트 스타일

처음부터 플레이어가 이해할 수 있는 일관된 게임 화면을 제작한다.

기존 상용 게임의 리소스를 무단 사용하지 않는다.

아트 방향:
- 2D SF 기계 세계관
- 어두운 청남색 배경
- 청록색 플레이어 기체
- 적은 붉은색 또는 주황색
- 에너지와 충격파는 노란색 또는 청색
- 깔끔하고 가독성이 좋은 HUD
- 과도하게 장식적인 UI 지양

제작 대상:
- 플레이어 기체
- 일반 적 4종
- 보스
- 기본 투사체
- 반동 충격파
- 피격 효과
- 폭발 효과
- 보호막
- 배경
- 타이틀 화면
- 업그레이드 아이콘
- HUD
- 결과 화면

별도 그래픽 파일이 제공되지 않은 경우, 단순 색상 사각형으로 방치하지 말고 가능한 범위에서 Unity의 Sprite, Mesh, Particle System, LineRenderer, 코드 기반 텍스처 생성 등을 활용하여 일관된 오리지널 아트 스타일을 구현한다.

외부 이미지 생성 도구를 사용할 수 있다면 자체 제작한 새 리소스를 사용해도 된다.

그래픽 리소스가 나중에 교체되더라도 코드 수정이 최소화되도록 설계한다.

# 16. MOD 시스템 전체 구현

이 프로젝트는 단순한 슈팅게임이 아니라 MOD를 지원하는 게임이다.

따라서 MOD 시스템은 선택 사항이 아니다.

반드시 완성해야 하는 핵심 기능이다.

MOD로 변경 또는 추가할 수 있는 요소:

- 플레이어 스킨
- 기체 기본 능력치
- 중력
- 추진력
- 무기
- 투사체
- 반동 공격
- 업그레이드
- 적
- 기존에 구현된 이동 패턴
- 스테이지
- 배경
- 사운드

게임의 기본 콘텐츠와 MOD 콘텐츠는 가능한 한 동일한 데이터 로딩 구조를 사용한다.

게임 실행 로직과 콘텐츠 데이터를 분리한다.

MOD의 기본 형식은 ZIP 패키지다.

패키지 구조 예시:

REBOUND_Mod/
  manifest.json
  data/
    weapons/
    upgrades/
    enemies/
    stages/
    flight/
  assets/
    sprites/
    audio/

manifest.json 필수 정보:
- schemaVersion
- modId
- name
- author
- version
- targetGameVersion
- content
- description
- license

MOD 작업:
- MOD 탐색
- ZIP 설치
- manifest 검증
- 버전 검사
- 콘텐츠 로딩
- 이미지 로딩
- 활성화
- 비활성화
- 충돌 감지
- 오류 기록
- 기본 게임 콘텐츠 복구

MOD Manager UI 구현:
- 설치된 MOD 목록
- MOD 이름
- 제작자
- 버전
- 설명
- 활성화 여부
- 활성화 버튼
- 비활성화 버튼
- MOD 폴더 열기
- MOD 새로고침
- 오류 내용 표시

MOD가 잘못되었더라도 게임 전체가 중단되지 않도록 한다.

실행 중인 게임의 상태가 불안정해질 수 있는 콘텐츠 변경은 다음 게임 시작 시 적용해도 된다.

보안 요구사항:
- 임의 C# 스크립트 및 DLL 실행 금지
- ZIP 경로 이탈 방지
- 압축 해제 크기 제한
- 파일 수 및 크기 제한
- 허용 확장자 검사
- 상대경로 검증
- 중복 ID 검사
- JSON 데이터 검증
- MOD 간 충돌 처리
- 예외 로그 기록

기존 콘텐츠의 교체와 신규 콘텐츠 추가를 구분하는 명시적인 규칙을 정의한다.

MOD 적용 순서는 결정적이어야 한다.

# 18. MOD 다운로드 서버와의 연동

MOD 다운로드 서버는 별도로 준비된 것으로 가정한다.

새로운 MOD 다운로드 서버를 구현하지 않는다.

프로젝트에 기존 다운로드 서버의 API 명세나 설정이 존재한다면 이를 분석하고 클라이언트 연동을 구현한다.

API 정보가 없다면:
- 임의의 서버 주소를 생성하지 않는다.
- 허구의 API를 구현하지 않는다.
- 로컬 MOD 설치, 활성화, 비활성화 기능을 완성한다.
- 서버 연결에 필요한 클라이언트 인터페이스를 분리한다.
- 실제 연동에 필요한 정보만 문서화한다.

이미 구현된 서버 코드가 있는 경우 이를 임의로 재작성하지 않는다.

# 24. 작업 수행 규칙

매우 중요하다.

- 일부 기능만 작성하고 종료하지 않는다.
- Phase 1 또는 프로토타입만 구현하고 멈추지 않는다.
- 사용자에게 기능별로 진행 허락을 반복해서 요구하지 않는다.
- 구현 가능한 전체 범위를 연속해서 개발한다.
- 필요하면 내부적으로 단계별 Git 커밋을 남긴다.
- 사용하지 않는 임시 코드를 제거한다.
- TODO만 작성하고 구현한 것처럼 보고하지 않는다.
- 실제 게임에서 작동하지 않는 모의 기능을 완성본으로 간주하지 않는다.
- 코드 구현뿐 아니라 씬, UI 연결, 데이터, 리소스, 테스트까지 수행한다.
- 게임에 필요한 기능을 임의로 삭제하거나 축소하지 않는다.
- 원본 게임의 저작권 리소스 및 구체적인 표현을 복제하지 않는다.

최종 목표는 **기획 문서나 예제 코드가 아니라 실제 실행되는 RE:BOUND 게임**이다.

지금부터 프로젝트를 확인하고 게임 전체 구현, 통합, 테스트, Windows 빌드까지 진행하라.
